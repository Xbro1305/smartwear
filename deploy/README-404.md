# Корректный HTTP 404 для несуществующих страниц (nginx)

Цель: несуществующие URL (мусорные адреса, удалённые товары/категории) должны
отдавать **HTTP 404** вместо 200, показывая при этом нашу React-заглушку `NotFound`.
Живые страницы и глубокие ссылки продолжают работать (200).

> Почему это не чинится на клиенте: HTTP-статус выставляет сервер (nginx) ещё до
> запуска React. Значит решение — на уровне nginx.

Файлы:
- `nginx-spa-404.conf` — конфиг server-блока.
- `njs/slug_validate.js` — проверка слага (категория/товар) в бэкенде.

---

## Вариант A — полный (рекомендуется): 404 в т.ч. для несуществующих товаров/категорий

Категории и товары живут как слаги в корне (`/muzhchinam`, `/some-product`).
Отличить живой слаг от мусора можно только спросив бэкенд — это делает njs.

**Требуется модуль njs** (`nginx-module-njs`):
```bash
# Ubuntu (репозиторий nginx.org) или:
sudo apt-get install nginx-module-njs
```

Установка:
1. Скопировать валидатор:
   ```bash
   sudo mkdir -p /etc/nginx/njs
   sudo cp deploy/njs/slug_validate.js /etc/nginx/njs/
   ```
2. Подключить модуль njs в главном `nginx.conf` (в самом верху, вне `http{}`):
   ```nginx
   load_module modules/ngx_http_js_module.so;
   ```
3. Взять `deploy/nginx-spa-404.conf` за основу своего server-блока и поправить:
   - `server_name` — ваш домен;
   - `root` — путь к собранному фронту (`vite build` → `dist`);
   - адрес бэкенда в `location /__be/` и в `proxy_set_header Host` (прод/тест API).
4. Проверить и перезагрузить:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

## Вариант B — простой (без njs): 404 только для неизвестных роутов

Если njs недоступен — оставьте из конфига только allowlist и `error_page`, убрав
блоки `auth_request`, `/__validate_slug`, `/__be/` и `js_import`. Тогда:

```nginx
location @spa {
    if ($is_known_route) { rewrite ^ /index.html last; }  # известные роуты → 200
    return 404;                                            # остальное → 404 (заглушка)
}
error_page 404 /index.html;
```

⚠️ Ограничение варианта B: **несуществующие товары/категории** (слаги в корне)
тоже получат 404 — но и **живые** товары/категории получат 404, потому что без
бэкенда их не отличить. Поэтому вариант B годится, только если у вас все реальные
категории/товары под известным префиксом (напр. `/catalog/...`), а корневых слагов
нет. В текущей реализации корневые слаги есть → нужен вариант A.

## Проверка (после деплоя)

```bash
# Известный роут — 200
curl -I https://ВАШ_ДОМЕН/catalog
# Мусорный адрес — 404
curl -I https://ВАШ_ДОМЕН/qwerty-not-exists-123
# Реальный товар/категория — 200
curl -I https://ВАШ_ДОМЕН/<живой-слаг>
```
Во всех случаях тело ответа — наш `index.html` (React покажет каталог или заглушку),
меняется только статус-строка (`200 OK` / `404 Not Found`).

---

## Важно

- Эти конфиги **не тестировались локально** — их нужно проверить на вашем сервере
  (`nginx -t`, затем `curl -I`), т.к. зависят от вашего окружения nginx и адреса API.
- Вариант A на каждый неизвестный путь делает 1–2 запроса к бэкенду (latency + бэкенд
  должен быть доступен). При недоступном API валидатор осознанно отдаёт 200
  (чтобы не «убить» индексацию живых страниц ложным 404) — см. `catch` в njs.
- Проверьте, что реальные `robots.txt` / `sitemap.xml` лежат в `root` и отдаются 200.
